# 招聘跟进垂直试点计划

> 状态：准备阶段，尚未使用真实用户数据

## 1. 为什么先选招聘跟进

招聘过程天然包含“未来可能值得联系”的理由，例如等待面试结果、准备复试、接受或拒绝 offer。它也包含 WakeIntent 必须处理的反例：结果提前出现、岗位取消、用户不想再谈、时间窗口变化和长时间未回应。

该场景的错误成本明确：过时询问会令人反感，漏掉有价值的关心则降低帮助感。它比泛化的“AI 更像活人”更容易定义可测指标。

## 2. 当前阶段

`pnpm demo:host` 只使用合成招聘对话，验证宿主编排与 outbox 边界，不证明真实用户价值。真实数据阶段必须在知情同意、可撤回、脱敏和最小留存条件下单独启动，不能直接拿私人聊天记录作为开源数据。

## 3. 对照实验

WakeIntent 与强 due-gated heartbeat 必须使用：

- 相同模型和模型参数；
- 相同完整对话和当前时间；
- 相同用户授权、免打扰和联系预算；
- 相同的消息生成与展示方式；
- 相同的最大模型请求预算。

强 baseline 在到期时读取最新上下文，因此不能故意设计成无脑提醒器。WakeIntent 要证明的是结构化生命周期和事件触发重验证是否产生额外收益。

## 4. 核心指标

- **误触达率**：不该联系却产生 `contact` 的比例；
- **漏触达率**：盲审认为值得联系但系统保持沉默的比例；
- **重复联系率**：同一理由被重复联系的比例；
- **失效清理时延**：新上下文已经使理由失效，到状态关闭之间的时间；
- **有效联系 precision**：所有联系中被盲审认为合理的比例；
- **模型成本**：每条时间线、每次有效联系的请求数、Token 和费用；
- **打扰感评分**：用户对时机、必要性和表达的独立评分。

## 5. 最小试点门槛

第一轮真实试点建议只招募少量明确同意的测试者，不进入生产通知渠道。系统先生成“建议联系卡片”，由测试者或研究人员确认，不自动发送。

进入自动投递实验前至少满足：

- 显式取消后的联系次数为 0；
- 重复联系率为 0；
- 自动 `cancel` / `resolve` 的错误终止率足够低，否则降级为人工确认；
- WakeIntent 至少在误触达、状态陈旧时长或总成本中的一项稳定优于强 baseline；
- 所有参与者可以查看、暂停、删除自己的联系意图。

如果只能让内部状态更复杂，却不能改善任何用户可见指标或成本指标，应把 WakeIntent 收缩为宿主 Agent 的可选生命周期模块，而不是扩大为平台。
