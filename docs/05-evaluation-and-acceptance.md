# WakeIntent v0.1 评测与验收方案

> 文档状态：Draft 0.1  
> 更新日期：2026-09-01

## 1. 评测目标

验证唯一核心假设：

> 显式建模并重验证 `ContactIntent`，是否比“记忆 + 定时 heartbeat”更准确地判断何时联系、何时终止以及何时保持沉默。

评测不是为了证明 WakeIntent 永远更好，也不以少数好看的 Demo 作为结论。

## 2. 对照组

### WakeIntent 组

- 从原始对话提取结构化候选意图；
- 保存证据、时间窗口、取消提示和打扰成本；
- 到评估点后执行确定性门控和语义重验证；
- 输出标准 Decision。

### Baseline 组

- 从原始对话保存简化的未来跟进记忆；
- 在固定 heartbeat 时读取记忆和最新上下文；
- 由同一模型输出相同 Decision 集合；
- 不使用 ContactIntent 的显式生命周期字段。

## 3. 公平性约束

两组必须使用：

- 相同模型与版本；
- 相同 temperature、最大输出和结构化输出能力；
- 相同原始对话及当前时间；
- 相同最新上下文和最大上下文预算；
- 相同用户授权、免打扰与预算信息；
- 相同决策标签和评分规则。

若 WakeIntent 使用额外信息，必须来自其先前结构化保存的意图，而不是评测人员临时补充答案。

## 4. 场景格式

每个场景至少包含：

- 场景 ID、版本、类别和语言；
- 初始对话事件；
- 时间轴上的后续对话与用户状态事件；
- 评估时间点；
- 期望是否创建意图；
- 每个评估点允许的决策集合；
- 必须引用或必须忽略的证据；
- 人工标注说明；
- 敏感性和授权要求。

## 5. 最小场景矩阵

| 类别 | 示例 | 关键期望 |
|---|---|---|
| 正常跟进 | 周五收到面试结果 | 在有效窗口联系 |
| 提前解决 | 用户提前说已拿到 offer | resolve，不重复询问 |
| 显式取消 | 不用再问这件事 | cancel，永久停止该意图 |
| 自然过期 | 结果窗口过去很久 | expire |
| 用户忙碌 | 最近明确说本周很忙 | defer 或 silent |
| 连续未回应 | 多次主动消息未获回应 | 降低触达，silent/defer |
| 多意图竞争 | 三个事项同时到期 | 只选高价值低打扰项 |
| 相似负例 | “我以前参加过一次面试” | 不创建意图 |
| 时间含糊 | “过阵子可能有消息” | candidate 或不创建，禁止伪造日期 |
| 上下文反转 | 先期待结果，后说不想谈 | cancel/silent |
| 时区边界 | 跨时区旅行 | 不在错误本地时间联系 |
| 敏感话题 | 医疗、财务、关系冲突 | 策略门控优先 |

v0.1 首个公开数据集建议不少于 40 个场景，每个核心类别至少 4 个；在此之前的少量场景只能称为开发 fixture，不能用于项目结论。

## 6. 核心指标

### 6.1 提取指标

- Intent precision / recall / F1；
- 证据引用准确率；
- 重复候选率；
- 时间窗口有效率。

### 6.2 决策指标

- Effective contact precision：建议联系的样本中真正应该联系的比例；
- False outreach rate：不应联系却输出 contact 的比例；
- Resolution detection recall：提前解决识别率；
- Cancellation detection recall：显式取消识别率；
- Expiry accuracy：过期判断准确率；
- Silent precision：输出 silent 的样本中确实应该沉默的比例；
- Decision macro-F1：各决策类别宏平均 F1。

### 6.3 系统指标

- 调度器触发次数、确定性资格检查次数和真实模型调用次数，三者分开记录；
- 输入/输出 token；
- 单场景估算费用；
- 端到端延迟；
- 非法状态转移数；
- 决策记录完整率；
- 相同场景多次运行的一致率。
- 意图已被最新上下文推翻、但系统仍保留为 active 的陈旧状态时长。

### 6.4 时间线唤醒实验

单个评估点会强制两组各做一次判断，不能证明 WakeIntent 比固定 heartbeat 少唤醒。成本实验必须覆盖至少 7 天和 30 天时间线，并区分三种实现：

- 朴素固定 heartbeat：每个周期都调用模型；
- 强基线：heartbeat 先用确定性 `dueAt` 索引过滤，只有到期记忆才调用模型；
- WakeIntent：只在 `notBefore` / `nextEvaluationAt` 到达或相关新上下文可能改变生命周期时进入重验证。

三组都要统计空转次数、模型调用、Token、错误触达和错过的有效联系。WakeIntent 若只优于朴素 heartbeat、却不能优于带确定性到期索引的强基线，则只能说明调度优化有效，不能证明 `ContactIntent` 是独立语义抽象。

## 7. 解释一致性

解释不能只看语言是否通顺，应检查：

- 引用证据是否真实存在；
- 解释是否与最终决策一致；
- 是否忽略了更高优先级的确定性门控；
- 是否虚构用户授权、时间或事件；
- 同一理由是否在 WakeIntent 与基线中被公平使用。

## 8. 测试分层

### L1 确定性单元测试

Schema、状态机、门控、时间边界、事件日志和幂等候选。必须离线、快速、每次提交运行。

### L2 合约测试

所有 Clock、Store 和 Model Adapter 必须通过相同 contract suite。

### L3 固定输出场景测试

使用 FakeModel 注入预设结构化输出，验证编排和状态变化，不评估模型能力。

### L4 真实模型评测

运行公开场景和基线。记录模型信息并缓存原始输出，不纳入默认单元测试。

### L5 人工复核

对含糊、敏感或多种合理答案的场景进行盲审。评审者不知道输出来自 WakeIntent 还是基线。

## 9. v0.1 验收门槛

### 工程验收

- 所有公开 Schema fixture 通过校验；
- 核心状态机和硬门控分支测试覆盖率达到 90%；
- fake clock 场景无真实等待；
- 运行失败时保留可重放 manifest；
- Core 不依赖具体模型 SDK、数据库或 Web 框架。

### 产品假设验收

在预先冻结的测试集上，相比基线：

- False outreach rate 有稳定下降；
- 解决、取消和过期识别至少不低于基线，并在总体上有可观改善；
- Silent precision 提升且没有以大幅牺牲有效联系召回率为代价；
- 多次运行结果的置信区间支持结论，而不是只报告最好的一次；
- 成本增量被完整披露。

在获得首轮数据前不写死具体提升百分比。首轮实验用于形成合理门槛，之后冻结评测协议再报告结果。

## 10. 防止自我欺骗

- 先冻结场景和评分规则，再调 Prompt；
- 开发集与最终测试集分开；
- 不删除失败样本，只能修正并版本化标注错误；
- 明确联系频率与软性联系许可分开标注；“未回复”不能自动覆盖用户明确要求的固定频率；
- 同时公开原始决策和汇总指标；
- 报告负面结果和成本；
- 不使用 WakeIntent 特有字段向基线泄露标准答案；
- 不以 Star、演示效果或主观“像真人”替代指标。

## 11. Alpha 收口规则

可行性验证不再以 40+ 场景作为启动产品化的前置条件。`evals/alpha-closure-longitudinal-v0.1.json` 已冻结 12 条连续时间线，覆盖有效联系、提前解决、显式取消、间接目标失效、无关上下文、全局免打扰及恢复、全局撤销授权、过期、连续未回应、明确频率和模糊未来负例。

本轮是有限的 Alpha GO/REVIEW 收口，而不是公开 benchmark：

- 固定最多 12 条，不允许为了挽救结果临时加题；
- 至少 10/12 通过；
- WakeIntent 用户可见误触达必须为 0；
- 提前解决、取消、间接失效、全局策略、过期、未回应和负例等安全场景必须全部通过；
- 强 baseline 必须保留完整累计上下文，并继续允许同一到期窗口批量决策；
- 通过后结束可行性论证并进入 Alpha 产品化；失败则审查是实现缺陷、模型不稳定还是抽象本身不成立，不无限追加实验。

真实评测入口默认仅输出计划，不读取 `.env`、不联网：

```powershell
pnpm eval:alpha-closure:plan
```

当前 12 条数据的保守请求上限为 84 次。收口 runner 强制关闭自动重试，并在候选或 baseline memory 超过冻结数量时立即终止该场景，因此 HTTP 尝试上限同样为 84。执行时会在每次 HTTP 尝试前持久化预算账本，并在每个场景结束后更新同一份报告；使用 `--resume=<report-path>` 续跑时复用稳定幂等键，且续跑与原进程共用 84 次硬上限。只有用户再次明确接受场景数、合成载荷、请求上限和费用后，才允许运行一个新的 `pnpm eval:alpha-closure:api` 轮次。运行一次完整收口后，不自动重复失败项或增加轮次。
