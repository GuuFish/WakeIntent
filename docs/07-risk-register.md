# WakeIntent 风险登记表

> 文档状态：Draft 0.1  
> 更新日期：2026-09-01

## 风险评分

- 概率：Low / Medium / High
- 影响：Low / Medium / High
- 优先处理：概率与影响至少一项为 High，或两项均为 Medium

| ID | 风险 | 概率 | 影响 | 应对措施 | 触发信号 |
|---|---|---|---|---|---|
| R-001 | 最终只是“记忆 + 调度器 + Prompt” | High | High | 独立 Schema、状态机、重验证接口和基线评测 | 无法在失效与沉默指标上优于基线 |
| R-002 | 与 OpenClaw inferred commitments 高度重合 | High | High | 聚焦框架无关协议和公开评测，不复制 Agent runtime | 差异只能通过宣传语解释 |
| R-003 | 过度工程化导致首版无法完成 | High | High | v0.1 排除真实投递、调度、客户端、lease 和多框架 | P1 前出现数据库、消息队列或 UI 工作 |
| R-004 | LLM 输出不稳定导致评测不可重复 | High | Medium | 多次运行、记录参数、报告置信区间、FakeModel 分层测试 | 同场景结论频繁翻转 |
| R-005 | 评测数据偏向 WakeIntent | Medium | High | 先冻结测试集、盲审、公开原始输出和负例 | Prompt 调整后同步修改测试答案 |
| R-006 | 主动联系造成骚扰或操控 | Medium | High | 授权、免打扰、预算、敏感策略优先；silent 为一等决策 | 模型绕过用户取消或反复联系 |
| R-007 | 解释看似合理但与真实证据不符 | High | Medium | 强制 evidence refs 和一致性检查 | 解释包含对话中不存在的事实 |
| R-008 | 敏感对话被写入日志或发送给模型 | Medium | High | 数据最小化、脱敏端口、合成公开数据 | 运行日志包含完整个人对话 |
| R-009 | 跨语言目标因 TypeScript 实现而落空 | Medium | Medium | JSON Schema 作为公开契约，Core 不暴露 Node 类型 | 外部实现必须复制 TS 内部逻辑才能接入 |
| R-010 | 时间与时区错误造成不合适联系 | Medium | High | 注入 Clock、UTC 持久化、时区场景测试 | 本地时间被当作 UTC 或 DST 场景失败 |
| R-011 | 状态与投递语义混淆 | Medium | High | contact 是决策；DeliveryEvent 后续独立建模 | 没有 receipt 却标记 contacted/delivered |
| R-012 | 项目范围过窄，缺乏真实采用 | Medium | Medium | 提供清晰适配端口，后期选择一个真实生态验证 | 只有自建 Demo 使用 Core |
| R-013 | 角色系统喧宾夺主，重新变成玩具 | Medium | Medium | 角色作为 Policy 扩展，核心评测不依赖角色 | README 和 Issues 只讨论人设与 UI |
| R-014 | 成本优势不成立 | Medium | Medium | 记录调用和 token；不预设一定省钱 | 重验证成本高于固定 heartbeat 且准确率无优势 |
| R-015 | relevance router 因多语言词片段或表面重合误路由 | High | Medium | 语言感知特征、完整审计、间接与负例成对评测、模型回退 | 路由理由依赖无意义字符片段或错误主题 |
| R-016 | 间接语义路由的额外模型调用抵消项目收益 | High | Medium | 明确影响本地路由、可配置轻量 router model、宿主对话回合复用、单独统计路由税 | router Token 占总成本过高且未带来误触达改善 |
| R-015 | 维护者依赖 AI 生成但无法维护代码 | Medium | High | 小提交、测试优先、设计记录、要求理解后合并 | 无法解释核心状态转移和错误路径 |

## 最高优先级风险的退出规则

### R-001：独立性失败

如果冻结测试集上连续两轮实验都不能在失效识别、误触达或沉默准确率上体现稳定优势，应停止扩展基础设施，重新评估是否将 WakeIntent 作为应用功能。

### R-003：范围失控

在 P4 真实模型结果出现前，任何 UI、真实渠道、分布式调度和多 Agent 功能都必须单独提出变更理由，不默认进入范围。

### R-006：用户伤害

任何允许模型覆盖显式取消、免打扰或敏感策略的设计均不得合并。角色策略永远低于用户控制策略。

## 开放问题日志

开放问题应在 Issue 或后续 ADR 中记录负责人、截止阶段和决策依据。当前包括：

- 许可证选择；
- Candidate 升级为 Active 的确认策略；
- 多参与者对话的目标身份模型；
- 敏感话题默认策略；
- 首个真实模型和首个生态适配器；
- 人工标注者之间意见不一致的处理规则。
