# Context-aware 有限对照实验

> 状态：已完成并停止比较。
> 冻结数据集：`packages/eval/fixtures/context-aware-v1.json`
> 机器可读原始结果：`reports/context-aware-comparison/2026-09-05T05-26-02.490Z.json`

## 要回答的问题

本实验只回答一个有限问题：

> 把未来联系理由保存为 `ContactIntent`，与每次醒来读取近期聊天并临时决定是否联系相比，在指定的长期场景中是否更可靠、更少误触达、更可解释，而且成本可以接受？

它不评测完整聊天产品、人格质量、消息文案、通知渠道或用户留存。

## 冻结设计

真实调用前固定 12 个合成场景：正常到期、提前完成、明确取消、自然失效、忙碌延期、连续不回复、多理由、长对话截断、进程重启、重复消息/评估、相似负例、spontaneous 闲聊。

两边使用：

- 同一模型：`gpt-5.5`；
- 同一 Responses API；
- 同一事件、当前时间、UTC 时区和用户状态；
- 同一最近 8 条原始事件预算；
- 同一检查点和期望行为。

WakeIntent 可以持久化 `ContactIntent`、生命周期和证据，这是被测处理。Context-aware baseline 不保存未来联系意图，但会读取同样的近期聊天、当前时间、用户状态和既往投递记录，并使用明确要求处理完成、取消、失效、忙碌、多主题和重复联系的强提示词。

正式运行前估计最多 75 次逻辑模型调用，网络重试后的硬上限为 120 次 HTTP 尝试。只执行一轮，不根据结果增补题目或重复运行。

## 原始结果

真实运行共 63 次 HTTP 尝试。WakeIntent 有 29 次逻辑模型调用，其中一次网络重试；Context-aware 主评测有 32 次；另有 1 次完整历史诊断。

| 指标 | WakeIntent | Context-aware |
|---|---:|---:|
| 官方计分通过率 | 17/20（85%） | 17/20（85%） |
| intent-driven 通过率 | 84.2% | 84.2% |
| 无理由误触达率（官方汇总） | 0% | 0% |
| 该沉默或延期时的准确率 | 100% | 100% |
| 有效联系精度 | 100% | 100% |
| 行为与理由格式一致 | 100% | 100% |
| 证据准确率 | 85% | 95% |
| 持久化生命周期可审计 | 100% | 不适用 |
| 逻辑模型调用 | 29 | 32 |
| 输入 Token | 15,991 | 16,954 |
| 输出 Token | 8,436 | 8,409 |
| 总 Token | 24,427 | 25,363 |

WakeIntent 的主评测 Token 是 baseline 的 96.3%。这里不能推导出“WakeIntent 一定更省钱”：样本很小，而且 baseline 的调用策略、提示词长度和真实产品唤醒频率都会改变结果。环境没有配置模型单价，所以费用为 `null`，含义是“未知”，不是免费。

## 场景观察

两种机制在正常到期、忙碌延期、进程重启、负例和不重复触达上都完成了预期行为。

WakeIntent 在两个场景表现出清楚的结构性收益：

1. 多理由：论文已提前完成而摄影课仍有效。WakeIntent 关闭论文理由，并在到期时只联系摄影课；baseline 在更新时把“已解决”标成“取消”，到期又漏掉摄影课。
2. 长对话截断：早期志愿活动理由退出最近 8 条聊天后，WakeIntent 仍能联系；baseline 保持沉默。额外给 baseline 完整历史后，它恢复为正确联系。这个诊断说明差异来自“保存了相关理由”，不是 WakeIntent 使用了更聪明的模型。

重复场景里，两边都没有重复联系。WakeIntent 共调用 2 次模型，baseline 调用 4 次，因为 WakeIntent 在首次联系后不再调度该理由，而 baseline 每次醒来仍需重新判断。

spontaneous 场景明确了能力边界：baseline 在轻松聊天后主动接梗，WakeIntent 没有创建长期意图并保持沉默。两种行为都按冻结规则判为正确。WakeIntent 本身不覆盖这类临时主动表达。

## 计分审计限制

运行后审计发现当前汇总器有两个已知限制。为避免在看到结果后改规则，本报告保留原始分数和原始结论，没有重新运行或重算：

1. 官方汇总排除了每个场景的首检查点。原始记录显示，baseline 在“自然失效”场景的首检查点把“明天 09:00”误读为当前时间并提前联系；这次误触达没有进入官方误触达率。
2. WakeIntent 在提前完成、明确取消和连续不回复场景中，已经在新事件到来时持久化关闭意图，并在原到期时间零调用、零联系。计分器只看原到期时是否又输出一次“已解决/已取消”标签，因此把三个正确保持沉默的检查点记为证据或识别失败。

这两个问题方向相反但都足以影响聚合数字。原始 JSON 保存了逐步决策、状态、审计事件和模型调用，可直接复核。任何新的计分规则都应作为新的冻结版本，在下一次独立实验前确定，不能覆盖这次结果。

## 结论

本实验采用预先登记规则产出的结论 2：

> **WakeIntent 有工程价值，但目前更适合作为主动聊天应用的内部子系统，与 Context-aware 层组合。**

支持这一判断的证据是：

- 持久化理由在长对话截断和多理由分流中带来实际收益；
- 重启和重复事件下保持一致；
- 每次建立、延期、取消、解决都留下来源证据与审计记录；
- 本次调用数和 Token 没有高于 baseline。

仍不足以支持“独立模块已经被充分证明”的原因是：

- 官方总分与 baseline 持平；
- 多数简单场景的用户可见结果相同；
- 长上下文诊断表明 baseline 在拿回完整历史后也能成功；
- 只有一个模型、一次运行、12 个合成场景，没有真实用户体验数据；
- 当前计分器的已知限制让更强结论不够稳妥。

## 下一步边界

这轮比较到此停止。合理的产品结构是：Context-aware 层负责 spontaneous 表达和整体对话气氛，WakeIntent 只负责有明确跨时间理由的 intent-driven 生命周期。

如果以后继续验证，应先发布一个新的冻结评测版本，明确把“此前已关闭、到期零调用”视为持久化状态命中，并把首检查点纳入误触达统计；然后有限重复不同随机种子或模型。不能修改本次原始报告来追求更高分。
